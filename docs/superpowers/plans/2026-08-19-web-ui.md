# apps/web — UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `apps/web` — the Next.js UI for streak-map — implementing every screen in the
approved design handoff on top of the already-complete `packages/core`/`packages/store`
foundation: Dashboard (populated + empty), Habit Detail, Habit Editor modal, Settings
(export/import, theme, shortcuts, about), and the Components-sheet dev reference screen.

**Architecture:** Next.js App Router + React + Tailwind CSS v4, UI-only per the three-layer
split (CLAUDE.md). State comes from Dexie via `useLiveQuery` (`dexie-react-hooks`) reading
`packages/store` directly — no Redux/Zustand, no server state. Design tokens are CSS custom
properties (dark is the default theme per CLAUDE.md; light is the alternate, fully specified,
toggled from Settings). A small `components/ui/` primitives layer (Button, Panel,
SegmentedControl, Stepper, ColorSwatchRow, Tooltip) is built once and reused by every screen,
rather than each screen hand-rolling inline styles the way the HTML prototype does.

**Tech Stack:** Next.js (App Router), React, TypeScript `strict: true`, Tailwind CSS v4,
`dexie-react-hooks`, Zod (import validation only — lives in `apps/web/lib`, not `packages/core`,
per the core-purity ruling below), Vitest + React Testing Library + jsdom for component tests,
Biome.

**Spec:** [docs/features/streak-map-spec.md](../../features/streak-map-spec.md) (product spec —
§2 scope, §3 data model, §4 brightness/streak algorithms already implemented in `packages/core`)
and [docs/features/prototypes/implementation.md](../../features/prototypes/implementation.md)
(the approved high-fidelity UI handoff — **the source of truth for this plan's visual and
interaction detail**; every task below cites the section it implements). The bundled
`docs/features/prototypes/streak-map-design-reference.html` is a live-in-browser reference for
exact spacing/color/hover behavior when a task's description is ambiguous — open it in a browser
and compare rather than guessing.

## Global Constraints

- **Ruling — implementation.md supersedes spec §2 F3 / §7 for the Dashboard layout:** the spec's
  original design prompt describes a single full-width "aggregate all-habits" hero grid at the
  top of the Dashboard. The later, approved, high-fidelity handoff (implementation.md, "final for
  this design pass") replaces that with a plain text check-in count in the header and gives each
  habit its own full 365-day grid instead. **Build implementation.md's Dashboard exactly as
  written — no aggregate hero grid.** (Confirmed with the human partner before writing this
  plan.) `packages/core`'s `aggregateLevels` function still exists and is fully tested — it is
  simply unused by v1's UI; do not delete it, a future screen may use it.
- **Ruling — dark is the default theme, not light:** implementation.md itself says "this
  reference defaults to light per the latest direction" but also says "wire both themes, default
  to whichever the team decides at build time." CLAUDE.md is more recent and explicit: "Dark mode
  is the default and the strongest design." **Default to dark**, both themes fully implemented
  and toggleable from Settings → Appearance, matching implementation.md's own token tables
  exactly for both.
- **`packages/core` stays dependency-free.** Zod lives in `apps/web/lib/schema.ts`, not
  `packages/core/src/schema.ts` — this repeats the ruling already made and enforced in the
  foundation plan (`.claude/hooks/core-purity.sh`, CI's `check:core-purity`). Do not add Zod (or
  any dependency) to `packages/core/package.json`.
- **Day keys are local `YYYY-MM-DD` strings, never derived via UTC** (CLAUDE.md, spec §3.2).
  Every place the UI needs "today," call `todayKey()` from `@streak-map/core` — never
  `new Date().toISOString().slice(0, 10)` or similar UTC-derived shortcuts.
- **Check-ins are unlimited per day, not a boolean toggle.** "Check in" always increments; there
  is no post-completion disabled state. The `−` undo button only appears once today's count > 0,
  floors at 0 (deletes the day's row at 0 — already implemented in `packages/store`'s
  `undoCheckIn`).
- **Intensity is never conveyed by color alone.** Every grid tile carries an `aria-label` with
  the same count+date text a tooltip would show, per implementation.md's "Contribution grid"
  section and the Accessibility bullet under it.
- **Every interactive element shows a visible focus ring on keyboard focus**
  (`box-shadow: 0 0 0 3px var(--focus-ring)`, implementation.md "Focus ring" section) — this must
  not be suppressed with `outline: none` alone; the box-shadow replaces the outline, it doesn't
  just remove it.
- **The `⌘K` command palette is explicitly out of scope** — implementation.md says it "is not
  part of the target product spec; the developer should omit it." No task in this plan builds it.
- **Exact dependency versions, never ranges** — root `.npmrc` already has `save-exact=true`; add
  every dependency via `pnpm add [-D] <pkg> --filter web`, never hand-type a version.
- **TypeScript `strict: true` everywhere**, extending the existing `tsconfig.base.json`.
- **Conventional Commits**, one commit per task's final step, using the
  [`commit` skill](../../../.claude/skills/commit/SKILL.md).
- **For UI work, verify in an actual browser before calling a task done** — every task below ends
  with `pnpm --filter web dev` and a manual check in the browser, not just green tests. Tests
  verify logic; only your eyes verify the design was actually followed.

```tsx
import './globals.css';

const workSans = Work_Sans({
  subsets: ['latin'],
  weight: ['400', '500', '600', '700'],
  variable: '--font-work-sans',
});

const plexMono = IBM_Plex_Mono({
  subsets: ['latin'],
  weight: ['400', '500', '600'],
  variable: '--font-plex-mono',
});

export const metadata: Metadata = {
  title: 'streak-map',
  description: 'A local-first habit tracker that turns consistency into a contribution grid.',
};

const THEME_INIT_SCRIPT = `
(function () {
  try {
    var stored = localStorage.getItem('streak-map:theme');
    var theme = stored === 'light' || stored === 'dark' ? stored : 'dark';
    document.documentElement.setAttribute('data-theme', theme);
  } catch (e) {
    document.documentElement.setAttribute('data-theme', 'dark');

  return (
    <html lang="en" className={`${workSans.variable} ${plexMono.variable}`} suppressHydrationWarning>
      <head>
        {/* biome-ignore lint/security/noDangerouslySetInnerHtml: trusted inline script, no user input */}

      </head>
```

Global Constraints ruling) is applied with no flash of the wrong theme. `suppressHydrationWarning`
is required because the script mutates `<html>`'s attributes before React can compare against its
server-rendered output.

- [ ] **Step 2: Write `lib/theme.ts`**

```ts
'use client';

export type Theme = 'light' | 'dark';

export const THEME_STORAGE_KEY = 'streak-map:theme';

export function getStoredTheme(): Theme {
  if (typeof window === 'undefined') return 'dark';
  const stored = window.localStorage.getItem(THEME_STORAGE_KEY);
  return stored === 'light' || stored === 'dark' ? stored : 'dark';
}

export function setStoredTheme(theme: Theme): void {
  window.localStorage.setItem(THEME_STORAGE_KEY, theme);
  document.documentElement.dataset.theme = theme;
}
```

```tsx
interface SegmentedControlProps<T extends string> {
  options: { value: T; label: string }[];
  value: T;
  onChange: (value: T) => void;
  'aria-label': string;
}

export function SegmentedControl<T extends string>({
  options,
  value,
  onChange,
  ...rest
}: SegmentedControlProps<T>) {
  return (
    <div
      role="radiogroup"
      aria-label={rest['aria-label']}
      className="inline-flex rounded-lg border border-border bg-elevated p-0.5"
    >
      {options.map((opt) => (
        <button
          key={opt.value}
          type="button"
          role="radio"
          aria-checked={opt.value === value}
          onClick={() => onChange(opt.value)}
          className={`focus-ring cursor-pointer rounded-md px-3 py-1.5 text-[13px] font-medium transition-colors ${
            opt.value === value ? 'bg-surface text-tx1 border border-border-hi' : 'text-tx3'
          }`}
        >
          {opt.label}
        </button>
      ))}
    </div>
  );
}
```

```tsx
interface StepperProps {
  value: number;
  min: number;
  max: number;
  onChange: (value: number) => void;
  label: string;
  'aria-label-decrease': string;
  'aria-label-increase': string;
}

export function Stepper({ value, min, max, onChange, label, ...rest }: StepperProps) {
  return (
    <div className="flex items-center gap-2">
      <button
        type="button"
        aria-label={rest['aria-label-decrease']}
        disabled={value <= min}
        onClick={() => onChange(Math.max(min, value - 1))}
        className="focus-ring h-7.5 w-7.5 cursor-pointer rounded-lg border border-border bg-elevated text-tx1 hover:border-border-hi disabled:cursor-not-allowed disabled:opacity-40"
      >
        −
      </button>
      <span className="min-w-17.5 text-center font-mono text-sm text-tx1">{label}</span>
      <button
        type="button"
        aria-label={rest['aria-label-increase']}
        disabled={value >= max}
        onClick={() => onChange(Math.min(max, value + 1))}
        className="focus-ring h-7.5 w-7.5 cursor-pointer rounded-lg border border-border bg-elevated text-tx1 hover:border-border-hi disabled:cursor-not-allowed disabled:opacity-40"
      >
        +
      </button>
    </div>
  );
}
```

The two `<button>`s are hand-rolled rather than using the shared `Button` component because they
need the disabled-at-bounds styling `Button` doesn't have.

- [ ] **Step 5: Write `ContributionGrid.tsx`**

```tsx
import { dateFromDateKey, enumerateWeekStartKeys, perHabitLevel, todayKey, trailingWindowKeys } from '@streak-map/core';
import type { DateKey } from '@streak-map/core';
import { Legend } from './Legend';
import { MonthLabels } from './MonthLabels';
import { Tile } from './Tile';
import { WeekdayLabels } from './WeekdayLabels';

const WINDOW_DAYS = 365;

interface ContributionGridProps {
  counts: Record<DateKey, number>;
  target: number;
  color: string;
  windowDays?: number;
  today?: DateKey;
}

function formatDisplayDate(key: DateKey): string {
  const date = dateFromDateKey(key);
  return date.toLocaleDateString('en-US', { month: 'short', day: 'numeric', year: 'numeric' });
}

function tileLabel(date: DateKey, count: number): string {
  if (count === 0) return `No check-ins on ${formatDisplayDate(date)}`;
  return `${count} check-in${count === 1 ? '' : 's'} on ${formatDisplayDate(date)}`;
}

export function ContributionGrid({ counts, target, color, windowDays = WINDOW_DAYS, today = todayKey() }: ContributionGridProps) {
  const days = trailingWindowKeys(today, windowDays);
  const firstDay = days[0];
  const weekStartKeys = enumerateWeekStartKeys(firstDay, today);

  const columns: DateKey[][] = weekStartKeys.map((weekStart) => {
    const week: DateKey[] = [];
    const start = dateFromDateKey(weekStart);
    for (let i = 0; i < 7; i++) {
      const d = new Date(start.getFullYear(), start.getMonth(), start.getDate() + i);
      const key = `${d.getFullYear()}-${String(d.getMonth() + 1).padStart(2, '0')}-${String(d.getDate()).padStart(2, '0')}`;
      week.push(key);
    }
    return week;
  });

  return (
    <div>
      <div className="overflow-x-auto">
        <div className="min-w-[800px]">
          <MonthLabels weekStartKeys={weekStartKeys} />
          <div className="flex gap-[3px]">
            <WeekdayLabels />
            {columns.map((week, weekIndex) => (
              <div key={weekStartKeys[weekIndex]} className="flex flex-col gap-[3px]">
                {week.map((date) => {
                  const inWindow = date >= firstDay && date <= today;
                  if (!inWindow) return <div key={date} className="h-[11px] w-[11px]" />;
                  const count = counts[date] ?? 0;
                  const level = perHabitLevel(count, target);
                  return (
                    <Tile
                      key={date}
                      date={date}
                      count={count}
                      level={level}
                      color={color}
                      isToday={date === today}
                      label={tileLabel(date, count)}
                    />
                  );
                })}
              </div>
            ))}
          </div>
        </div>
      </div>
      <Legend color={color} />
    </div>
  );
}
```

Days from `gridStartWeek` up to `firstDay - 1` (padding at the start of the first week, before
the 365-day window technically begins) render as blank spacers rather than tiles — they're outside
the counted window but needed to keep full Mon–Sun columns.

```tsx
export function HabitEditorModal({ mode, habit, onClose }: HabitEditorModalProps) {
  const [name, setName] = useState(habit?.name ?? '');
  const [description, setDescription] = useState(habit?.description ?? '');
  const [startDate, setStartDate] = useState(habit?.startDate ?? todayKey());

        description: description.trim() || undefined,

        description: description.trim() || undefined,
        color,
        interval,

        startDate,
```

```ts
const WINDOW_DAYS = 365;

export function useHabitCheckIns(habitId: string, windowDays = WINDOW_DAYS): Record<DateKey, number> | undefined {
```

```tsx
'use client';

import Link from 'next/link';
import { useState } from 'react';
import type { Habit } from '@streak-map/core';
import { computeStreakStats, todayKey } from '@streak-map/core';
import { checkIn, undoCheckIn } from '@streak-map/store';

export function HabitCard({ habit }: HabitCardProps) {
  const [busy, setBusy] = useState(false);
  const counts = useHabitCheckIns(habit.id);
  const today = todayKey();
  const todayCount = counts?.[today] ?? 0;

  if (counts === undefined) return null;

  const stats = computeStreakStats(
    { interval: habit.interval, target: habit.target, startDate: habit.startDate, counts },

    setBusy(false);
  };

  const handleUndo = async () => {
    setBusy(true);
    await undoCheckIn(db, habit.id, today);
    setBusy(false);
  };

  const settled = todayCount > 0;

  return (
    <div className="rounded-xl border border-border bg-surface p-5.5">
      <div className="mb-4 flex flex-wrap items-center justify-between gap-3">
        <Link href={`/habit/${habit.id}`} className="focus-ring flex items-center gap-2.5">

          <span>

            <span className="block font-mono text-[11px] text-tx3">{stats.currentStreak}-day streak</span>
          </span>
        </Link>
        <div className="flex items-center gap-2.5">
          {todayCount > 0 && <span className="font-mono text-[11px] text-tx3">{todayCount} today</span>}
          <button
            type="button"
            disabled={busy}
            onClick={handleCheckIn}
            className={`focus-ring cursor-pointer rounded-xl px-4.5 py-2 text-[13px] font-medium transition-colors ${
              settled ? 'bg-elevated text-tx2' : 'border border-border-hi text-tx1'
            }`}
          >
            Check in
          </button>
          {todayCount > 0 && (
            <button
              type="button"
              aria-label="Undo last check-in"
              disabled={busy}
              onClick={handleUndo}
              className="focus-ring h-7.5 w-7.5 cursor-pointer rounded-[10px] border border-border text-tx3 hover:border-border-hi hover:text-tx1"
            >
              −
            </button>
          )}
        </div>
      </div>

      <ContributionGrid counts={counts} target={habit.target} color={habit.color} today={today} />
      <StatsStrip stats={stats} />
```

```ts
import { z } from 'zod';
import type { CheckIn, Habit } from '@streak-map/core';

export const EXPORT_SCHEMA_VERSION = 1;

const dateKeySchema = z.string().regex(/^\d{4}-\d{2}-\d{2}$/, 'Expected YYYY-MM-DD');
const isoTimestampSchema = z.string().datetime();

const habitSchema = z.object({
  id: z.string(),
  name: z.string().min(1),
  description: z.string().optional(),
  color: z.string(),
  interval: z.enum(['daily', 'weekly']),
  target: z.number().int().min(1).max(20),
  startDate: dateKeySchema,
  order: z.number().int(),
  archivedAt: isoTimestampSchema.optional(),
  createdAt: isoTimestampSchema,
  updatedAt: isoTimestampSchema,
  deletedAt: isoTimestampSchema.optional(),
}) satisfies z.ZodType<Habit>;

const checkInSchema = z.object({
  id: z.string(),
  habitId: z.string(),
  date: dateKeySchema,
  count: z.number().int().min(1),
  createdAt: isoTimestampSchema,
  updatedAt: isoTimestampSchema,
  deletedAt: isoTimestampSchema.optional(),
}) satisfies z.ZodType<CheckIn>;

export const exportSchema = z.object({
  schemaVersion: z.literal(EXPORT_SCHEMA_VERSION),
  habits: z.array(habitSchema),
  checkins: z.array(checkInSchema),
});

export type ExportPayload = z.infer<typeof exportSchema>;

export function buildExportPayload(habits: Habit[], checkins: CheckIn[]): ExportPayload {
  return { schemaVersion: EXPORT_SCHEMA_VERSION, habits, checkins };
}

export function parseImportPayload(json: unknown): ExportPayload {
  return exportSchema.parse(json);
}
```

```ts
'use client';

import { useEffect } from 'react';

function isTypingTarget(target: EventTarget | null): boolean {
  if (!(target instanceof HTMLElement)) return false;
  const tag = target.tagName;
  return tag === 'INPUT' || tag === 'TEXTAREA' || tag === 'SELECT' || target.isContentEditable;
}

export function useKeyboardShortcut(
  key: string,
  handler: (e: KeyboardEvent) => void,
  options: { enabled?: boolean } = {},
): void {
  const { enabled = true } = options;

  useEffect(() => {
    if (!enabled) return;

    const listener = (e: KeyboardEvent) => {
      if (e.isComposing || isTypingTarget(e.target)) return;
      if (e.key.toLowerCase() !== key.toLowerCase()) return;
      handler(e);
    };

    window.addEventListener('keydown', listener);
    return () => window.removeEventListener('keydown', listener);
  }, [key, handler, enabled]);
}
```

```tsx
      <DashboardHeader
        checkInsThisYear={checkInsThisYear ?? 0}
        year={new Date(todayKey()).getFullYear()}
      />
      {habits.length === 0 ? (
        <EmptyState onCreateHabit={() => setEditorOpen(true)} />
      ) : (
        <section>
          <h2 className="mb-4 text-[13px] font-medium text-tx2">Habits</h2>
          <div className="flex flex-col gap-4">
            {habits.map((habit, i) => (
              <div
                key={habit.id}
                className={i === focusedIndex ? 'rounded-xl shadow-[inset_0_0_0_1.5px_var(--tx2)]' : ''}
              >
                <HabitCard habit={habit} />
              </div>
            ))}
          </div>
        </section>
      )}

      <button
        type="button"
        onClick={() => setEditorOpen(true)}
        className="focus-ring fixed bottom-6 left-1/2 flex -translate-x-1/2 items-center gap-2 rounded-[20px] bg-cta-bg px-5.5 py-3 text-sm font-medium text-cta-text shadow-[0_4px_16px_rgba(0,0,0,0.1)] hover:bg-cta-hover"
      >
        New habit <span className="font-mono text-[11px] opacity-70">n</span>
      </button>

      {editorOpen && <HabitEditorModal mode="create" onClose={() => setEditorOpen(false)} />}
      <ShortcutsOverlay open={shortcutsOpen} onClose={() => setShortcutsOpen(false)} />
    </main>
  );
}
```

`checkIn(db, ...)` here is fired without `await` deliberately — the shortcut handler is
synchronous by the hook's type; `useLiveQuery` picks up the resulting DB write reactively once
the promise resolves, same as the click handlers elsewhere. This is consistent with how
`HabitCard`'s own click handlers already behave.
